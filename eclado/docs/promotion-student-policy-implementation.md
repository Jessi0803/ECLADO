## 實作方式

增量檔案為 `supabase-promotion-student-policy.sql`；唯讀安裝檢查為同名 `-verify.sql`。

- 活動新增 `allow_student_price_stacking`、`instructor_reward_eligible`，皆預設 true 保留原行為。`promotion_student_policy_settings.enabled` 首次安裝為 false，且既有自動分配功能亦須啟用，新規則才生效。安裝不批次修改雙十一活動。
- 新規則僅作用於符合學生價資格的商城／代客 AUTO 件。MANUAL 以明確旗標保留舊成交價、既有活動及返饋行為；優惠券專用、滿額贈／滿件贈不接受本次排除設定。
- 保留舊分配核心。需要新政策的重疊群組以有預算的完整件數搜尋比較「商品實付最低、同額活動優先、同額較少返饋、既有活動與件數排序」。不使用舊的最大名目折抵剪枝或單活動全範圍捷徑。
- 單一買贈群組有可證明的壓縮路徑：免費件仍取完整比較池最低價，付費件先取放棄學生折扣成本最低者，再比較排除返饋與固定商品順序。不逐件展開9999件。
- 其他複雜組合維持128格／整單20000搜尋節點上限；超限明確拒絕報價，不回傳未證明最佳的結果。test 雲端已完成六規格60件買6送1及單規格9999件買3送1的純 helper 量測；不能將單一買贈測量外推至完整 RPC 或任意重疊配置。

## 金額與歷史相容

商品列保留學生基準單價，避免改寫庫存來源、既有 AUTO 價格驗證及原始商品件數。活動以該方案的正確單價計門檻與折抵，並將不適用學生折扣的金額作為獨立價格調整。

例如會員價800、學生價720、四件買3送1：小計2880，活動折抵800，活動件不適用學生價加回320，商品實付2400，相較學生方案再省480。第五件維持學生價720與返饋。

新 `student_price_restoration` adjustment 的 `amount` 與既有表一樣為非負數，但代表加回；總折抵為「一般折抵金額合計－student_price_restoration 合計」。不能直接把所有 `amount` 加總當作總折抵。商城／代客權威報價、歷史訂單顯示、列印、付款查詢投影均已配合；銀行仍只使用原權威 `payment_amount`，沒有改動銀行金額算法。

`automatic_allocations` 保存活動政策版本、整組件數、活動計價單價、學生基準單價及排除旗標。返饋只讀建單時已存快照，不讀日後活動設定。重複規格輸入在活動分配時合併，返饋排除件數再分配回原商品列，避免重複排除。全單零返饋仍保留完整私有快照及既有零額 Ledger 流程。

報表只新增返饋適用／排除件數及排除原因；師資比較價格仍不公開給學生。未修改歷史快照、原收款證據、取消／退貨或冪等流程。滿額贈／滿件贈資格基礎及優惠券套用順序保持原規則；運費／優惠券不納入擇優。

## 發布與回復順序

1. 在 test 備份涉及函式定義／owner／ACL、活動設定、約束與功能開關。核對既有版本及 migration markers；未知版本須中止，不能跳過檢查硬套。
2. 安裝增量 SQL，確認新開關 false、活動政策 true、權限及唯讀 verify。不要重跑舊 setup／舊分配 migration 來覆蓋新版約束或函式。
3. 部署配套前端與付款 API。確認兩個付款查詢入口均保留價格加回明細，過期報價被拒絕。
4. 在 test 對應雙十一配置設定政策，啟用新開關，進行真實 RPC 報價／建單回滾、完整 Schema／權限及桌面手機驗收。隔離測試不替代此步驟。
5. 正式發布與活動設定變更另安排操作確認；備份後重查正式活動ID及設定，不以名稱批次盲改。既有會員對象、時間及庫存規則保持不變。
6. 回復供新報價使用時，關閉 `promotion_student_policy_settings.enabled`，恢復舊疊加／返饋行為並要求舊報價重新確認。保留新欄位、價格調整類型、已成立訂單與帳務；不刪快照、不用全庫還原。已建單付款及退貨仍依原始快照。
