# 自動活動適用對象

正式資料庫已於 2026-10-17 完成部署及回滾式功能驗證；詳見 [正式部署紀錄](automatic-promotion-audience-production-2026-10-17.md)。前端尚未部署。

自動活動可多選一般會員、美容師、師資、經銷商、內部人員，另有獨立的「允許訪客」開關。支援百分比折扣、固定金額折抵、滿額贈、滿件贈。可以只允許訪客；不能將所有身分與訪客全部取消。

既有活動與新活動的初始值均包含五種會員身分及訪客，維持原有行為。優惠券專用活動繼續由優惠券方案決定適用對象。

## 部署

1. 在最新的活動、優惠券、贈品、會員價格、合併出貨及已啟用的代客下單 migration 之後，執行 `supabase-automatic-promotion-audience.sql`。
2. 確認 SQL 完成後才部署前端。否則舊版儲存 RPC 不會保存新欄位，畫面可能顯示成功但設定未生效。
3. 未來若重建相關計價／活動儲存函式，須在同一部署流程最後再次執行此 migration。migration 可重跑，會保留已安裝的價格及運費邏輯；遇到不符預期的函式結構會整批停止。

不修改既有訂單或歷史價格快照。不改變自動折扣擇優與優惠券疊加規則。活動資格以產生報價及建立訂單當下的身分為準。

## 計價與顯示

後端在選擇自動活動之前檢查身分，涵蓋舊版折扣、新版折扣及自動贈品。代客下單使用客人的身分與會員 ID，不能使用操作管理員的身分。內部資格判斷及原始活動儲存函式禁止前台直接呼叫。

前台首頁、商城、商品卡片、商品明細、購物車與結帳預覽使用相同的對象篩選。公開活動讀取政策保持現狀；此欄位限制優惠資格，不作為活動資料保密機制。真正折扣仍由伺服器驗算。

## 驗證

- 隔離 PostgreSQL：`PGLITE_MODULE=/path/to/@electric-sql/pglite/dist/index.js node --test tests/integration/automatic-promotion-audience-db.test.cjs`
- 後台：`npx playwright test tests/admin.spec.ts --project=chromium --grep '自動活動|活動指定商品可全選|建立原子百分比|百分比與固定金額|活動限定商品可以被指定'`
- 前台：`npx playwright test tests/eclado-frontend.spec.ts --project=chromium --project=mobile-chrome --grep '未符合身分|活動資格依目前|現貨、預購、活動折扣|優惠券專用活動不會'`

資料庫測試使用真實的價格、贈品及代客計價函式，涵蓋五種身分、訪客、最低資格篩選、僅訪客、無效輸入、權限、儲存失敗回滾、舊客戶端欄位省略及重跑 migration。

## 回復

若要恢復所有人的自動活動資格，可由有權限的管理員將活動的五種身分及訪客全部勾選。前端可以回復到前一版本，資料欄位與 SQL 保留；舊客戶端儲存時省略對象欄位不會重設既有設定。若須移除後端限制，應先將所有活動恢復原適用對象，再另行準備 SQL 回復，不直接重跑舊版計價 migration 覆蓋目前的付款或運費修正。
