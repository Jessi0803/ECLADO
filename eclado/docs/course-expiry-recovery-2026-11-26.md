# 歷史逾期報名恢復（僅 TEST 驗證）

本次只在 `/tmp/eclado-course-payment-resume` 實作，尚未部署、推送或恢復正式兩筆訂單。

目的：針對舊規則因「付款期限已過」自動取消的美容師本人付費報名，在銀行確實確認原交易逾期未付款後，保留原報名、原訂單及價格快照，恢復待付款並延長至課程開始前，重新提供四種付款方式。這不是一般未付款訂單隨時切換付款方式。

## SQL 與保護條件

`supabase-course-expiry-recovery.sql` 接在 payment-resume、payment-reminders、enrollment-retention 後執行。SQL 本身不自動恢復任何舊單；每筆必須另由受信任的服務端呼叫 `recover_expired_course_enrollment`。

- 只接受目前仍是 `pending` 的未收款單、單人美容師本人報名、精確取消原因「付款期限已過」，且取消操作者為空。人工取消、已付款、待人工確認、有案件、重複有效報名均拒絕。
- 確認原最新交易已過期、銀行已簽章查證 `1C250` 或 `1M250`，銀行查證時間不得超過五分鐘。服務角色 RPC 本身不能代替外部銀行查證。
- 沿用原訂單／報名 ID、金額、價格與建立時間；付款期限改至課程開始時間。
- 原取消原因、時間、操作者及前後付款期限保存於具 RLS 的恢復帳本；匿名／會員不能讀寫。
- 原付款嘗試保留，標記退出續付並保存銀行逾期碼。會員摘要不再提供該筆舊連結或付款方式。
- 首次重新選擇付款時建立 `attempt_no + 1` 與新的銀行編號；後續沿用選定方式，不提供一般切換功能。
- 相同恢復請求重跑不會清空新付款資料，並沿用課程／訂單鎖避免並行重複建立付款。
- 若已退出續付的舊交易意外傳回收款，改走人工核對；重複收款不重複成立報名或購物金。
- 保留原建立時間，所以未付款提醒若日後啟用，可能立即符合首次提醒條件。本次未啟用通知或購物金排程。
