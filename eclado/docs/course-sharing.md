# 課程網址與分享預覽

2026-11-25：正式 Supabase 已套用 `supabase-course-slugs.sql`。本次提交包含前後台、課程分享 API 與正方形圖片調整。

## 選填代稱

- 後台「課程網址代稱」留白時，繼續使用 `/courses/{UUID}`。
- 填寫後，使用 `/courses/{slug}`；識別碼網址回傳不快取的 302，轉向當前代稱網址。清除代稱後，識別碼網址恢復直接顯示，避免永久轉址快取造成失效。
- 現有課程新增欄位預設 NULL，不會自動產生或回填代稱。
- 代稱限定 3～100 個小寫英文字母、數字與連字號；儲存時去除首尾空白並轉小寫。禁止保留字、UUID 格式及重複代稱。
- 目前不保留舊「代稱」別名。已分享代稱後建議保持不變；原 UUID 連結始終會指向目前的網址。
- 報名、付款、購物金與通知仍使用 UUID；`/{slug}/register` 會先解析成 UUID 再載入會員資料。

## 分享預覽

- `api/course-page.js` 回傳含課名、課程概述、封面入口與 canonical 的初始 HTML，同時保留前台程式載入。
- `api/course-share-image.js` 透過公開課程 RPC 驗證可見性後讀取該封面，轉成完整等比 JPEG；不使用管理員金鑰、不公開 Zoom 或報名資料。
- 未上架、排程尚未到時及不存在的課程回傳 404。暫時無法載入則回傳 503，不快取失敗結果。
- LINE 的實際預覽與既有卡片快取，仍須待公開測試網址確認；localhost 無法讓 LINE 伺服器讀取。

## 未來部署順序

先完成測試庫驗證與使用者確認，再於獲准後部署：

1. 在既有 `supabase-course-publication-schedule.sql` 之後執行 `supabase-course-slugs.sql`。
2. 部署前後台與分享 API（sharp 需為正式依賴）。
3. 確認空代稱、設定代稱、UUID 轉向、複製連結、登入返回及付款維持正常。

本機資料庫測試使用隔離 PGlite；不會連線 Supabase。
