# 代客開單：部署與驗證

目前為本地實作；本次沒有執行正式 SQL、部署付款 API、commit 或 push。

## 部署順序

1. 先確認既有會員全域／商品折數、歷史訂單、購物金結帳、庫存分配、盤點及付款重試 migrations 已完成。
2. 執行完整 `supabase-assisted-orders.sql`（含 begin / commit），不要只複製片段。函式版本不符時會中止並回滾，不要移除格式檢查硬執行。
3. 執行唯讀 `supabase-assisted-orders-verify.sql`，確認全部 true（包含 wallets_allowed）。若已執行早期僅信用卡／ATM 版本，請重新執行完整新版 migration，會升級付款方式限制。
4. 更新獨立 Payment API：`payment-api/server.js` **及** `payment-api/assisted-orders.js`，使用原有環境變數並重啟服務。單純 push 前端不能完成這一步。
5. 部署前端／後台，再驗證新增入口與客戶付款連結。三部分未齊前不要建立正式代客單。

Migration 只對 `admin_assisted` 啟用提前保留庫存；一般網站訂單維持原有付款後分配庫存，歷史訂單仍不分配庫存。既有盤點函式與追加單 trigger 會加入這種來源的處理，不能在部署後直接重跑舊版相關 SQL 覆蓋這些 guard。

## 管理員操作

- 後台「訂單管理」→「新增代客訂單」。需同時具有 orders.write、members.read、catalog.read 權限。
- 也可從會員詳情，點選與「匯入訪客訂單／補登歷史訂單」並排的「代客開單」，直接帶入該會員及已有的聯絡、預設發票資料；未送出的申請資料不提供此入口。
- 選訪客或既有會員；會員可搜尋姓名／Email／手機。商品規格單價預帶目前該身份的適用價格，再由管理員設定成交價。
- 填收件資訊、發票及信用卡／Apple Pay／Google Pay／虛擬帳號。Apple Pay／Google Pay 沿用原永豐行動支付參數與失敗重試流程；裝置及銀行端可用性仍依原付款服務。運費依既有規則預帶，可免運／自訂；異動原運費或豁免專業最低訂購額需填內部原因。
- 成交價為最終價，不再疊促銷、優惠券、贈品、購物金；不參與追加／合併出貨。
- 確認建立後，訂單即成立、保留庫存、開始 48 小時付款期限。現貨不足不成立；允許客訂的商品可保留預購缺貨紀錄。
- 複製私人付款連結給客戶。不需登入即可確認保存的商品、金額、收件及發票資料並付款；不包含內部原因、操作紀錄、成本或庫存。
- 訂單詳情「取得客戶付款連結／開單紀錄」可再次取得連結並查看僅後台可見的建立者、價格及例外原因。
- 成立後不能改商品／成交價／收件人或會員歸戶；確定銀行結果與訂單狀態後，依既有取消規則取消，再重建。不可永久刪除代客單稽核紀錄。
- 會員仍從會員中心查自己的訂單；訪客可用短查詢碼＋手機查詢。連結到期不刪除訂單、不代表已付款。

## 重送與付款異常

- 同一次送出保留同一 UUID；同 UUID／相同內容找回原單，不產生第二筆。內容不同時拒絕，不自動取消。
- 同分頁重新開啟表單會找回未結束的開單操作；只保存操作 ID，不保存收件個資。清除瀏覽器資料或換分頁後不具備跨操作的自動重複判斷，請先從訂單列表查原單。
- 明確拒絕且無「重複、處理中、逾時」等不確定訊息，可對原單重試。
- 網路逾時、回應缺失、銀行回報重複或成功後儲存失敗：不釋放付款 claim、不自動換銀行單號、不自動取消。重新讀取後仍無資訊時，需要管理員／工程人員以銀行紀錄及原 provider_order_no 對帳；不可僅因前端失敗就清除 claim 或重建。此版本未提供讓客服強制解除不確定 claim 的按鈕。
- 已付款不重扣庫存；取消不重複回補。取消後才收到經既有機制驗證的入帳通知，會恢復 paid 並重新分配一次；庫存不足保留缺貨紀錄，需人工確認款項及履約。
- 盤點將未付款代客單已保留、尚未出貨的數量納入現場實體庫存；突發盤虧可轉為缺貨，不會在取消時把不存在的實體庫存加回。

- 瀏覽器桌機／手機：代客開單、報價覆寫、付款失敗保留原單、權限、客戶公司發票與 ATM；另回歸一般結帳、購物金、訪客查詢、盤點、身份定價，共 30 項。
- 另補 Apple Pay／Google Pay 後台選擇至客戶付款跳轉桌機／手機 4 項。
- Payment API `npm test`：45 項（銀行呼叫／正式資料均為 mock）。
- 真實 PostgreSQL 語意的隔離 PGlite 測試：執行 migration 並重跑，驗證原子回滾、同 ID 找回、權限、鎖定、庫存付款取消生命週期、盤點及晚到入帳。
- `npm run build` 成功；既有大型 chunk 警告仍存在。專案未設定獨立 typecheck／lint script。
- 尚未以真實銀行付款驗證；正式環境端到端測試須在上述三部分部署完成後，經管理者同意安排。
