# 會員全域與商品折數部署

## 範圍

- 管理員：系統設定 → 會員定價，設定師資／經銷商／內部人員全域折數。
- 商品編輯：三身份各自覆寫折數；所有規格共用。
- 留空沿用全域；10 折不打折；個別值取代全域，不相乘。
- 一般會員仍市場價；美容師仍專業價；免運、最低訂購與追加資格不變。
- 原本取消身份倍率的商品一次轉成三身份倍率 1（10 折）。不再使用舊旗標計價。
- 新商品預設三身份均留空。全域初始值沿用資料庫，SQL 不重設為固定值。

## 部署順序

1. 確認目前付款／優惠／購物金／身份及商品儲存相關 migrations 已安裝。
2. 在 Supabase SQL Editor 執行 `supabase-member-pricing.sql` 全檔。任何來源函式不符合預期時整個交易會回滾，不應跳過防呆自行執行部分片段。
3. 執行 `supabase-member-pricing-verify.sql`：首列檢查均應為 true；確認全域值及舊固定專業價商品。
4. 部署新版前端並重新整理後台，以重新取得 `member_pricing.manage` 權限。
5. **在 SQL 與新版前端兩者完成前，不要修改全域或商品折數。** 舊前端仍假設 70%／65%／50%，新前端才支援即時設定。
6. 在本地／正式使用測試會員確認商品覆寫、規格、購物車、優惠與付款金額；正式真金流測試需另外授權。

若先部署前端而未執行 SQL，折數欄位會停用，全域設定不允許儲存，不會將假定預設值写入資料庫。

不要在本 migration 之後重跑舊定價／內部人員完整 setup：舊種子 UPSERT 可能將已設定的全域倍率重設。此檔本身可重跑，不重新覆蓋已設定的折數。

## 安全及一致性

- 全域：`member_pricing.manage` 僅授予 admin／super_admin；商品個別折數沿用 catalog.write。
- 全域儲存會鎖定三身份資料並比對原值；商品儲存比對原商品折數。衝突時重新載入，不直接覆蓋。
- 商品設定與規格在原有單一 RPC 交易內儲存。
- 價格修改寫入既有 audit_logs，可查閱全域與商品變更前後值。
- 商品、規格與購物車使用 catalog 同次回應的設定；支援 Realtime 更新及切回頁面重新載入。
- 價格改變會使既有優惠碼預覽失效，需要重新套用。
- 新前端建立訂單提交預期單價；後端自行計價，不採信客戶單價。若不一致，整個訂單建立交易拒絕，提示重新確認。
- 不更新已成立 orders 的金額、商品／價格快照或既有付款單。

## 已完成測試類型

- 折數驗證、三身份獨立、個別覆寫、舊資料相容。
- 桌面／手機後台設定、取消、版本衝突、商品小編權限、SQL 未部署。
- 前台商品與規格價格、舊身份／付款／購物金／發票／優惠券回歸。
- 隔離 PostgreSQL/WASM 中執行實際 migration、報價及商品 save；驗證重跑不覆蓋、helper ACL、稽核與舊訂單不变。

隔離 DB 測試為 `tests/integration/member-pricing-db.test.cjs`。使用暫存的 PGlite 套件執行，不是新增網站 runtime 相依。重跑時指定：

```sh
PGLITE_MODULE=/absolute/path/to/@electric-sql/pglite/dist/index.js node --test tests/integration/member-pricing-db.test.cjs
```

SQL 尚未在正式 Supabase 實際套用；並非完整正式金流驗收。
